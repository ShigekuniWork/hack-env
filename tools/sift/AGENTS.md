# sift の作業ガイド

作業前に [README.md](README.md) で利用仕様、[ARCHITECTURE.md](ARCHITECTURE.md) で責務と依存関係を確認してください。

## 設計と変更の方針

- `main.go` は起動、最終的なエラー表示、終了コードを扱う薄いエントリーポイントに保つ。
- CLI・実行環境との接続と実行制御を区別する。前者は引数、入出力先、ファイルの寿命を扱い、後者は条件の準備とストリーム処理を組み合わせる。
- 条件の準備、条件の評価、ストリーム処理を区別する。同じパッケージ内でも責務の境界を保つ。
- 条件の準備では解釈・検証・評価の構成を行い、行の処理を始める前に評価できるフィルタを作る。
- 条件の評価は一行の値を受け取って判定する。引数の表記、ファイルパス、ストリームの読み書きに依存させない。
- ストリーム処理は準備されたフィルタに各行の判定を依頼し、一致した行を書き出す。条件の解釈や検証を行の処理に持ち込まない。
- 正規表現の生成と通常のチェックは条件の解釈・検証を共有する。生成先の制約は生成時のエラーとして扱い、通常のチェックに持ち込まない。
- 現在は CLI・実行環境との接続と実行制御を `internal/cli`、条件の準備・評価、正規表現の生成とストリーム処理を `internal/filter` に配置している。
- 現在のパッケージ依存は `main` → `cli` → `filter`。パッケージの配置と設計上の責務を区別し、分割する場合も条件の評価が実行環境へ依存しない方向を保つ。
- 新しい抽象化やパッケージは、具体的な責務の分離に必要な場合に追加する。名称は処理の目的に合わせる。
- 依頼に関係する範囲を変更し、既存の作業内容を保持する。

## Go コードの書き方

- 検証、準備、実行、後処理など、意味のある処理の区切りに空行を入れる。
- 値の取得と直後のエラーチェックは一まとまりにする。
- 複数のフィールドや処理を含む構造体リテラル・関数は、読みやすく改行する。
- 組み込み関数と重なる変数名を避け、責務が伝わる名前を使う。
- 公開する型・関数・メソッドとパッケージには、目的が分かるコメントを書く。
- 整形と静的検査は、モジュールルートの `.golangci.yaml` に従う。

## エラーとリソース管理

- エラー型は責務を持つパッケージの `errors.go` に定義する。
- 原因となるエラーを保持し、`Unwrap` や `%w` で `errors.Is` / `errors.As` に対応する。
- 各層はエラーを呼び出し側へ返す。処理の途中でプロセスを終了しない。
- ファイルを開いた側が閉じる。呼び出し側から受け取ったストリームを勝手に閉じない。
- 書き込み、出力のフラッシュ、ファイルのクローズの失敗も扱う。

## 保持する動作

仕様変更の依頼がない限り、次の動作を維持してください。

- 通常のチェックでは入力省略時は標準入力、出力省略時はカレントディレクトリの `sift.txt` を使う。
- `regex` コマンドは入力を読み込まず、既定で標準出力へ1つの PCRE2 正規表現を出力する。複数条件の AND を保つ。
- `-` による標準入出力の指定を受け付ける。
- 条件は実行前に検証し、不正な条件で出力ファイルを作成・上書きしない。
- 入力と出力が同じファイルの場合は、上書き前にエラーにする。
- 複数の条件は AND で評価し、Unicode による文字の判定と行の順序を維持する。
- 行単位で処理し、入力全体をメモリに保持しない。

## 検証

Go コードを変更した場合は、モジュールルート（このディレクトリの親）で以下を実行してください。

```sh
golangci-lint fmt
golangci-lint run ./...
go test ./...
go vet ./...
```

lint の指摘は原因を修正し、検査設定の緩和や理由のない抑制で回避しないでください。
振る舞いを変更した場合は、正常系・境界値・失敗時の動作を確認するテストを必要な範囲で追加・更新します。
ファイルを使うテストは一時ディレクトリで実行し、実際の入力や出力を上書きしないようにします。
実行できなかった検証があれば、その内容と理由を報告してください。

## ドキュメント

- 利用方法や条件の仕様を変えた場合は `README.md` を更新する。
- 責務、依存関係、処理の流れを変えた場合は `ARCHITECTURE.md` を更新する。
- パッケージの依存関係と責務の構造を分けて説明する。同一パッケージ内の責務も記述する。
- `ARCHITECTURE.md` はハイレベルな設計を記述し、関数ごとの説明や実装手順を並べない。
